# MyLibrary → GitHub Pages: шаги с нуля

Инструкция от пустого аккаунта до рабочей ссылки. Занимает минут 10.

**Какой вариант заливаем:** «2 файла» — `index.html` + `free-books.zip`. Всего 4 файла,  
структуру папок держать не нужно, ошибиться почти негде. Вариант с папкой `books/`  
описан в конце.

---

## СНАЧАЛА ПРОЧТИ: что чинилось и что залить прямо сейчас

В читалке нашлись пять настоящих проблем: часть книг вообще не открывалась, часть  
грузилась медленно, а оформление текста и выделение выглядели сломанными.  
Все пять уже исправлены в этой сборке.

**1. EPUB не читались вообще.** Почти все EPUB-конвертеры пишут заголовок  
самозакрытым тегом `<title/>`. Браузер в HTML-режиме считает это не закрытым тегом,  
а открытым `<title>` — и заглатывает в него **весь текст книги**. В итоге `<body>`  
остаётся пустым, и книга выглядит «битой». Таких документов было 100%:  
в файле «48 законов власти» — 75 из 75, в «Замке» Кафки — 29 из 29.  
Теперь такие теги разворачиваются в парные до разбора (`prepXhtml`).

**2. FB2 не читались вообще.** Две причины сразу:
- В русских FB2 почти всегда `windows-1251`, а читалка декодировала наугад → «кракозябры».  
  Теперь кодировка берётся из XML-заголовка файла.
- В FB2 полно сущностей вроде `&nbsp;` и `&mdash;`, которых XML не знает, — на них  
  парсер падал с ошибкой. Теперь они подменяются символами до разбора.

**3. Книги грузились долго.** Раньше весь архив с текстами (11.6 МБ) был **вшит прямо  
в HTML** — файл весил 16.5 МБ, и браузер обязан был скачать все 16.5 МБ прежде, чем  
показать хоть что-то. Теперь архив лежит отдельным файлом, а `index.html` весит  
**326 КБ** — в 50 раз меньше. Плюс при открытии книги распаковывается только она  
одна, а не весь архив целиком.

**4. Внешний вид.** Текст книги выглядел «как попало», и главная причина была не в  
шрифте: текст был **выключен по ширине**, а браузер **не умеет переносить русские  
слова** — словаря переносов для русского в Chrome нет. Из-за этого между словами  
появлялись пробелы шириной в 3–4 знака: «— Бы&nbsp;&nbsp;л&nbsp;&nbsp;бы&nbsp;&nbsp;гвардии&nbsp;&nbsp;он».  
Это и было то самое «не красиво».

Теперь:

- **выключка по умолчанию — по левому краю**: пробелы нормальные, строка читается ровно;  
  если хочется по ширине — есть переключатель **«Выключка»** в настройках (на широком  
  экране, планшете или ноутбуке, выключка по ширине выглядит хорошо);
- внизу вместо тесной серой строки — **счётчик и полоса прогресса**:  
  `Глава 1 из 14 · стр. 1 из 23 · 0%`;
- заголовок главы — по центру, с короткой чертой под ним;
- ссылки внутри текста — цвета темы, а не браузерный синий;
- цитаты — с чертой слева, подписи автора — курсивом справа, картинки — со скруглением;
- уважается системная настройка «уменьшить движение» (для тех, кому мешают анимации).

**5. Выделение текста было почти не видно.** Текст выделялся, но подсветка была  
почти одного цвета со страницей: контраст 1.45:1 на светлой теме и 1.40:1 на сепии.  
Понять, что именно выделено, было невозможно.

Причина — подсветка рисовалась как **26% акцентного цвета темы**. На светлой теме  
это еле различимый сиреневый, а на сепии акцент (коричневый) почти совпадает  
с фоном (кремовым). Одной общей пропорцией задачу не решить: на сепии и в тёмной  
теме акцентный цвет стоит ровно **между** цветом текста и фоном, поэтому при любой  
плотности либо пропадает подсветка, либо текст под ней.

Теперь плотность подобрана отдельно под каждую тему, а цвет текста внутри  
выделения задан явно:

| Тема | Было | Стало |
| --- | --- | --- |
| Светлая | 1.45:1 | **3.17:1** |
| Сепия | 1.40:1 | **2.72:1** |
| Тёмная | 1.53:1 | **3.50:1** |

Это контраст подсветки к фону страницы (норма WCAG для таких элементов — 3:1);  
текст под подсветкой везде держит 4.8–5.5:1, то есть читается. На сепии 2.72:1 —  
предел: выше можно только ценой читаемости текста. Цифры получены замером  
реальных пикселей настоящей страницы в Chromium, а не на глаз.

### Что нужно сделать

В репозитории `my-library` заменить **один файл**:

| Файл | Было | Стало |
| --- | --- | --- |
| `index.html` | 333 485 байт | **334 633 байта** |
| `free-books.zip` | не менялся | не менялся |

Порядок:

1. Открой <https://github.com/abdullah66999/my-library>
2. Кнопка **Add file** → **Upload files**

> **Почему книга «Загружаем архив книг…» висит пару секунд при первом открытии:**  
> это скачивается `free-books.zip` (11.6 МБ) — один раз, дальше он берётся из кэша  
> браузера и не качается заново. Вторая и все следующие книги открываются за доли  
> секунды. Проверено в настоящем Chromium: первая книга — 3.1 с, вторая — 0.4 с  
> и **ноль** сетевых запросов. Если хочешь, чтобы и первая открывалась мгновенно —  
> залей вариант с папкой `books/` (описан в конце файла).

> **В консоли браузера может мелькнуть `404 /books/free-001.txt`** — это читалка  
> один раз за сессию проверяет, нет ли рядом папки `books/` с быстрым вариантом.  
> Ошибка безвредная: не найдя папку, читалка просто берёт архив. Больше этот  
> запрос не повторяется.

## Шаг 2. Создать репозиторий

1. Нажми **`+`** в правом верхнем углу → **New repository**.
2. **Repository name**: `mylibrary` (латиница, без пробелов).
3. **Description** — можно пусто.
4. **Public** — обязательно. Поставь галочку именно на Public.
5. **Add a README file** — не ставь галочку.
6. **Create repository**.

Ты попадёшь на пустую страницу репозитория с подсказками.

> **Почему только Public:** GitHub Pages для приватных репозиториев работает лишь на  
> платном плане Pro. На бесплатном приватный репозиторий отдаёт 404.

## Шаг 3. Загрузить файлы

1. На странице репозитория найди ссылку **`uploading an existing file`** (в блоке  
   «Quick setup — if you've done this kind of thing before»). Если не видишь —  
   кнопка **Add file** → **Upload files**.
2. Открой папку с распакованными файлами.
3. Выдели все 4 файла и **перетащи их в окно браузера**.  
   Если `.nojekyll` не видно — перетащи 3 оставшихся, это не критично.
4. Дождись, пока все файлы появятся в списке (у `free-books.zip` это займёт  
   несколько секунд — 11.6 МБ).
5. Внизу поле **Commit changes** → напиши `first version` → нажми зелёную кнопку  
   **Commit changes**.

Файлы должны оказаться в корне репозитория — рядом друг с другом, не в подпапке.

> **Не перетаскивай саму папку** `mylibrary-pages-2files` — тогда файлы окажутся  
> внутри подпапки и сайт не найдёт их. Нужно открыть папку и выделить файлы внутри.

## Шаг 4. Включить GitHub Pages

1. В репозитории открой вкладку **Settings** (вверху справа, рядом с Code / Issues).
2. В левом меню найди раздел **Pages**.
3. Блок **Build and deployment** → **Source**: выбери **Deploy from a branch**.
4. Появится блок **Branch**: выбери **`main`** и папку **`/ (root)`**.
5. Нажми **Save**.
6. Подожди 1–2 минуты. Обнови страницу — сверху появится зелёная плашка  
   со ссылкой вида:
   ```
   https://твой-логин.github.io/my-library/
   ```

Вкладка **Actions** покажет, что деплой прошёл (зелёная галочка).

## Шаг 5. Проверить

1. Открой ссылку `https://твой-логин.github.io/my-library/` в браузере.
2. Должен появиться каталог книг. Нажми «Читать» на любой — текст должен открыться.
3. Дополнительно проверь, что архив на месте: открой  
   `https://твой-логин.github.io/my-library/free-books.zip` — начнётся скачивание.  
   Если 404, значит архив не загрузился, вернись к шагу 3.

## Бот на Python (`bot.py`)

В папке `my_library` лежит новый скрипт бота — `bot.py`.

**Важно понимать:** бот **не влияет** на то, открывается EPUB или FB2. Разбор книг  
живёт целиком в `index.html`. Единственное, что бот реально решает, — какую ссылку  
открыть. Старый `main.py` отправлял на `https://my-library-black.vercel.app/` — это  
**другая, старая сборка** (там нет `free-books.zip`, поэтому бесплатные книги в ней  
не работали вовсе). Новый `bot.py` открывает GitHub Pages.

### Запуск

**Самый простой способ:** открой папку в VS Code и нажми **F5**  
(или зелёный ▶ в левом верхнем углу). Всё, бот работает.

Настройки для этого уже лежат в папке `.vscode/`:

| Файл | Что делает |
| --- | --- |
| `launch.json` | кнопка ▶ / **F5** запускает именно `bot.py` с правильной папкой |
| `settings.json` | прибит интерпретатор с установленными пакетами — VS Code перестаёт подчёркивать импорты |
| `tasks.json` | запасной путь: **Ctrl+Shift+B**; там же задача «Проверить: токен на месте?» |

Остановить бота — **Ctrl+C** в терминале или красный квадрат ■ в VS Code.

**Через терминал** (если удобнее так):

```bash
cd "C:\Users\Fozzi\WorkBuddy AI\2026-09-12-21-23-21"
python bot.py
```

Токен бот берёт из `.env` — файл лежит **рядом с `bot.py`**. Впиши туда токен:

```
BOT_TOKEN=123456:AA...
WEB_APP_URL=https://abdullah66999.github.io/my-library/
```

Если делаешь **нового** бота: `@BotFather` → `/newbot` → имя и username →  
BotFather выдаст токен, вставь его в `.env`.

### Что бот делает сам, чтобы «просто работало»

- **Ставит пакеты**, если их нет. При запуске проверяет `python-telegram-bot` и
  `python-dotenv`, и при отсутствии сам вызывает `pip install -r requirements.txt`.
  То есть файл можно перенести на чистую машину и запустить — без подготовки.
  Проверено на чистой venv: поставил 9 пакетов и запустился.
- **Находит `.env` от своего расположения** (`Path(__file__).parent / ".env"`),
  а не от текущей папки — работает при запуске из любого места.
- **Пишет понятные ошибки вместо стеков.** Нет токена — скажет, какого файла
  не хватает и по какому пути. Нет сети — скажет, что проверить (интернет, VPN,
  файрвол), вместо 160 строк трассировки `httpx`.
- **Не светит токен в консоль.** `httpx` по умолчанию печатает каждый запрос
  вместе с URL, а в URL лежит токен — это заглушено.
- **Не шумит безобидными ошибками.** Например, нажатие кнопки, пока бот был
  выключен, даёт `Query is too old` — раньше это писа́лось как `[ERROR]`,
  теперь молча пропускается.

### Если бот не запускается

Три ошибки, которые встречались на практике.

**1. `start : Не удается найти указанный файл` / `InvalidOperationException`**

```
PS C:\Users\Fozzi> start bot.py
```

Две причины сразу:

- **не та папка** — `bot.py` лежит не в `C:\Users\Fozzi`, поэтому файл просто не найден;
- **`start` в PowerShell — это не «запустить Python»**, а алиас для `Start-Process`
  (открыть файл программой по умолчанию). Python так не запускается.

Правильно:

```powershell
cd "C:\Users\Fozzi\WorkBuddy AI\2026-09-12-21-23-21"
python bot.py
```

**2. `Не найден токен бота`**

Значит `.env` пустой или лежит не рядом с `bot.py`. Проверить, что бот видит токен:

```powershell
python -c "import bot; print(bool(bot.TOKEN))"
```

Должно напечатать `True`.

**3. Токен вписан в код вместо `.env`**

Классическая ловушка — вставить токен первым аргументом `os.getenv()`:

```python
# ТАК НЕ РАБОТАЕТ: первый аргумент — это ИМЯ переменной, а не её значение.
# Python ищет переменную окружения с названием из 46 символов, не находит
# и возвращает второй аргумент — пустую строку. Бот падает с «Не найден токен».
TOKEN = os.getenv("8993130717:AAH...", "").strip()

# ПРАВИЛЬНО: имя переменной, а значение — в .env
TOKEN = os.getenv("BOT_TOKEN", "").strip()
```

Плюс токен в коде — это утечка: файл может уехать в git. В проекте есть `.gitignore`,  
который закрывает `.env`, но если токен уже побывал в файле — надёжнее  
перевыпустить его: `@BotFather` → `/revoke` → выбрать бота → новый токен в `.env`.

**Проверка токена без запуска бота:**

```powershell
python -c "import bot, urllib.request, json; print(json.load(urllib.request.urlopen(f'https://api.telegram.org/bot{bot.TOKEN}/getMe'))['result']['username'])"
```

Напечатает username бота, если токен живой.

### Что бот делает

- **📖 Открыть библиотеку** — запускает читалку (кнопка-WebApp внутри Telegram).
- **➕ Добавить книгу** — принимает файл EPUB / FB2 / PDF / TXT до 20 МБ.
- При старте сам ставит кнопку меню в чате, чтобы читалка была в один тап.

### Чего бот не может

Присланный боту файл **не появляется в читалке сам**. Читалка работает в браузере и  
хранит книги в памяти устройства (IndexedDB), а бот — на сервере. Это два разных  
места. Поэтому свои книги удобнее добавлять **внутри читалки** кнопкой «Добавить» —  
тогда они сохранятся на телефоне и будут доступны офлайн.

Чтобы книга, присланная боту, реально попадала в читалку, нужен сервер-посредник  
(FastAPI + база). Заготовки под него в папке уже есть (`auth/`, `database/`,  
`storage/`, `web/sync.js`) — но это отдельная работа, скажи, если нужно.

### Про `.env`

В `.env` лежит токен бота. Раньше он был вписан прямо в `main.py` и не был защищён —  
достаточно было `git add .`, чтобы токен уехал в публичный репозиторий. Теперь есть  
`.gitignore`, который закрывает `.env` и папку `books/`. Проверено:

```
$ git check-ignore -v .env
.gitignore:3:.env    .env
```

> Токен, который лежит в старом `main.py` и в `.env`, — **засветившийся**.  
> Он не попал в публичный репозиторий (там только `index.html`), но лучше  
> перевыпустить его: `@BotFather` → `/mybots` → бот → **API Token** → **Revoke**.

## Если что-то не работает

| Что видишь                               | Причина                                     | Что делать                                            |
| ---------------------------------------- | ------------------------------------------- | ----------------------------------------------------- |
| Страница 404                             | Pages ещё не собрался                       | подожди 2–3 минуты, обнови                            |
| Страница 404 и репозиторий приватный     | Pages недоступен на бесплатном плане        | Settings → General → внизу Change visibility → Public |
| Открывается список файлов, а не читалка  | нет файла с именем `index.html`             | переименуй или загрузи именно `index.html`            |
| Показывает исходный код                  | открыта ссылка `github.com/.../blob/...`    | нужна ссылка `логин.github.io`                        |
| Каталог есть, книга не открывается       | `free-books.zip` не загрузился              | шаг 3 заново, проверь шаг 5                           |
| «На сервере нет free-books.zip»          | файл лежит не в корне                       | перенеси в корень репозитория                         |
| «В браузере закончилось место под книги» | переполнено хранилище браузера              | удали пару книг из библиотеки                         |
| Ошибка EPUB: «не найдено текстовых разделов» | в файле нет текста, только картинки, или это DRM | открой файл в другой читалке; если и там пусто — файл пустой |
| Ошибка FB2: «повреждён или недопустимые символы» | файл битый или это не FB2              | проверь, что файл открывается в другой читалке        |
| Книга открылась, но текст «кракозябрами» | неизвестная кодировка файла                | напиши — добавим кодировку в список                   |
| Первое открытие бесплатной книги долгое  | скачивается `free-books.zip` (11.6 МБ)     | один раз за сессию; либо залей вариант с `books/`     |
| Между словами в книге огромные пробелы   | включена выключка **по ширине**, а переносов русских слов в браузере нет | Настройки → **Выключка** → «По левому краю» |
| Хочется выключку по ширине               | на телефоне она рвёт строку                | включай её на планшете/ноутбуке, где строка длинная   |

## Как обновить файлы потом

1. Открой файл в репозитории (например `index.html`).
2. Значок карандаша → правь текст → **Commit changes**.
3. Для замены целиком: **Add file → Upload files** → перетащи новый файл с тем же  
   именем → GitHub сам предложит перезаписать.

Сайт обновится через 1–2 минуты. Если браузер показывает старое — Ctrl+Shift+R.

## Вариант с папкой `books/` (быстрее грузит книги)

Отличие: вместо `free-books.zip` заливаешь папку `books` со 100 текстовыми файлами.  
Тогда при открытии книги качается ~435 КБ вместо 11.6 МБ — заметно лучше, если  
читаешь с мобильного интернета.

Порядок тот же, но в шаге 3:

1. Перетащи в браузер файлы `index.html`, `og-cover.png`, `.nojekyll`.
2. Перетащи **папку `books` целиком** (не её содержимое). GitHub сохранит структуру.
3. Commit.

Проверка: открой `https://твой-логин.github.io/my-library/books/free-001.txt` —  
должен показаться текст «Капитанской дочки». Если 404 — папка не загрузилась  
или её содержимое легло в корень без папки.

```bash
cd путь/к/mylibrary-pages-2files

git branch -M main
git remote add origin https://github.com/ТВОЙ-ЛОГИН/mylibrary.git
git add -A

```

Дальше — шаг 4 (включить Pages).

> Внимание: `free-books.zip` весит 11.6 МБ. Это нормально — GitHub блокирует только  
> файлы больше 100 МБ, а через веб-интерфейс — больше 25 МБ. Но если позже добавишь  
> файл тяжелее 25 МБ, веб-загрузка его не примет, понадобится git.
