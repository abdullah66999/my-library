# MyLibrary для GitHub Pages — вариант «2 файла»

Минимальный набор для заливки: **`index.html` + `free-books.zip`**. Ничего раскладывать
по папкам не нужно.

| Файл | Что это | Размер |
|---|---|---|
| `index.html` | читалка | 0.3 МБ |
| `free-books.zip` | все 100 текстов одним архивом | 11.6 МБ |
| `og-cover.png` | картинка для превью-карточки в Telegram | 27 КБ |
| `.nojekyll` | чтобы GitHub Pages не прогонял файлы через Jekyll | 0 |

Страница весит 0.3 МБ вместо 15.8 МБ — именно поэтому она теперь открывается
в Telegram, а не показывает белый экран. Архив подтягивается один раз, при первом
открытии любой книги, и дальше всё летает.

## Как залить

1. В репозитории удали старый `MyLibrary.html`.
2. **Add file → Upload files** → перетащи все 4 файла сразу.
3. **Commit changes**.
4. Settings → **Pages** → Source: `Deploy from a branch`, Branch: `main`,
   папка `/ (root)` → **Save**.
5. Открывай `https://<логин>.github.io/<репо>/` — и только эту ссылку,
   не `github.com/.../blob/...` и не `raw.githubusercontent.com`.

## Чем отличается от варианта с папкой `books/`

- **Этот вариант:** 4 файла, но при первом открытии книги качается 11.6 МБ целиком.
- **Вариант `mylibrary-pages/`:** 104 файла, зато одна книга — ~435 КБ.

Если читаешь помногу и подряд — разницы почти нет. Если заходишь за одной книгой
с мобильного интернета — лучше вариант с папкой.

## Частые грабли

- **Приватный репозиторий.** GitHub Pages для приватных репозиториев работает только
  на плане Pro. На бесплатном — 404.
- **Ссылка на `blob` или `raw`.** Отдаётся исходный код, а не страница. Нужен `github.io`.
- **Открытие двойным щелчком с диска.** По `file://` браузер не отдаёт `free-books.zip`.
  Для локальной проверки: `python -m http.server` в этой папке, затем `http://localhost:8000`.
- **Pages не включён.** Settings → Pages → Source должен быть `Deploy from a branch`.

## Превью в Telegram

В `index.html` есть строка `content="og-cover.png"`. Если карточка не появилась —
замени на полный адрес: `https://<логин>.github.io/<репо>/og-cover.png`.

## Настоящий Telegram Mini App

@BotFather → `/newapp` → выбираешь бота → вставляешь ту же `github.io`-ссылку.
Требуется HTTPS (у Pages он есть) и публичный доступ. После этого внутри страницы
`Telegram.WebApp` получит `initData` и включатся тактильный отклик, тема и кнопка «Назад».

## Если книга не открывается — читаем сообщение

Теперь читалка пишет конкретную причину прямо во всплывающей плашке:

| Сообщение | Что случилось | Что делать |
|---|---|---|
| «На сервере нет файла books/free-001.txt — папка books не загружена в репозиторий» | файлов книг нет по этому адресу | загрузи папку books в корень репозитория, сохранив структуру |
| «Страница открыта с диска (file://)…» | файл открыт двойным щелчком | нужна ссылка http/https, локально — python -m http.server |
| «Сервер вернул 404 …» | Pages ещё не собрался или файл лежит не там | подожди 1–2 минуты, проверь Settings → Pages |
| «В браузере закончилось место под книги. Удалите несколько книг» | переполнено хранилище (IndexedDB) | удали пару книг из библиотеки |
| «(файл.epub): EPUB: не найдено текстовых разделов…» | файл повреждён, защищён DRM или это не EPUB | проверь файл в другой читалке |

Проверить, что файлы реально лежат на сервере, можно прямо в браузере: открой
https://ЛОГИН.github.io/РЕПО/books/free-001.txt — должен показаться текст книги.
Если 404, значит папки books на месте нет.
